🔧 Troubleshooting Gateway & NAT

Panduan lengkap mendiagnosis, menganalisis, dan memperbaiki permasalahan pada Internet Gateway dan Network Address Translation (NAT).

Pendahuluan

Internet Gateway adalah perangkat (bisa berupa router atau server) yang menghubungkan jaringan lokal (LAN) ke jaringan publik (internet). Sedangkan NAT (Network Address Translation) adalah mekanisme yang memungkinkan banyak perangkat dengan IP privat dapat mengakses internet melalui satu atau beberapa IP publik. Troubleshooting pada gateway dan NAT menjadi keterampilan krusial bagi administrator jaringan, karena kegagalan pada komponen ini akan melumpuhkan akses internet seluruh klien di jaringan lokal.

Pada topologi di atas, Router Mikrotik bertindak sebagai gateway. Ether1-publik terhubung ke internet dengan IP publik (misal 202.123.123.x), sedangkan Ether2-lokal terhubung ke switch dan melayani jaringan lokal 192.168.88.0/24. Server dan klien menggunakan gateway 192.168.88.1 serta DNS yang sama. NAT berperan menerjemahkan IP privat 192.168.88.x menjadi IP publik saat keluar ke internet.

A. Prosedur dan Teknik Pemeriksaan Permasalahan pada Internet Gateway

1. Pendekatan Sistematis Troubleshooting

Proses troubleshooting yang efektif mengikuti langkah-langkah berikut:

  1. Kumpulkan informasi – catat gejala, waktu kejadian, perubahan terakhir, dan konfigurasi yang berlaku.
  2. Lokalisasi masalah – tentukan apakah masalah terjadi di sisi fisik (kabel, port), perangkat (switch/router), atau konfigurasi (IP, routing, NAT).
  3. Isolasi komponen – pisahkan perangkat keras, perangkat lunak, dan akun pengguna untuk mengidentifikasi sumber utama.
  4. Perbaiki – terapkan solusi yang tepat, baik dengan konfigurasi ulang, penggantian hardware, atau penyesuaian aturan firewall.
  5. Verifikasi – uji kembali koneksi dan pastikan masalah benar-benar terselesaikan.
  6. Dokumentasi – catat penyebab dan solusi untuk referensi di masa mendatang.

2. Permasalahan Umum pada Gateway dan NAT

Berikut adalah jenis-jenis masalah yang paling sering dijumpai:

  • Koneksi fisik bermasalah – kabel putus, konektor longgar, atau port switch/router mati.
  • Konfigurasi IP salah – gateway default tidak sesuai, subnet mask keliru, atau IP duplikat.
  • Routing tidak aktif – fitur IP forwarding (ip_forward) tidak diaktifkan pada Linux, atau routing dinamis tidak berjalan.
  • Aturan NAT tidak tepat – rule MASQUERADE atau SNAT tidak ada, atau salah interface.
  • Firewall memblokir – aturan filter di iptables atau firewall router menghalangi lalu lintas.
  • DNS tidak berfungsi – client tidak bisa meresolve nama domain karena DNS server tidak dapat diakses.
  • Keterbatasan resource – overload koneksi, connection tracking penuh, atau bandwidth habis.

3. Alat Bantu (Tools) Diagnostik

Beberapa tools yang sangat berguna untuk mendiagnosis masalah gateway dan NAT:

  • ipconfig / ifconfig – melihat konfigurasi IP pada client dan server.
  • ping – menguji konektivitas dasar ke gateway, DNS, dan internet (misal ping 8.8.8.8).
  • tracert / traceroute – melacak jalur paket untuk mengetahui di hop mana paket terhenti.
  • netstat / ss – melihat koneksi aktif dan port yang terbuka.
  • iptables -L -t nat – menampilkan aturan NAT di Linux.
  • arp – memeriksa tabel ARP untuk konflik alamat MAC.
  • tcpdump / wireshark – menganalisis lalu lintas paket secara mendalam.
💡 Praktik terbaik: Mulailah dengan ping ke gateway (192.168.88.1). Jika gagal, masalah ada di lapisan 2 (switch/kabel) atau konfigurasi IP client. Jika berhasil, lanjutkan ping ke IP publik (misal 8.8.8.8). Jika gagal, periksa aturan NAT dan routing pada router.

4. Interpretasi Pesan PING

Hasil perintah ping memberikan petunjuk penting tentang status jaringan:

PesanArti & Tindakan
Reply from ... Koneksi berhasil – tidak ada masalah.
Destination Unreachable Host tujuan tidak dapat dijangkau. Periksa rute, gateway, dan pastikan tujuan aktif.
Time Exceeded TTL (Time To Live) habis – kemungkinan ada loop routing atau hop terlalu banyak.
Redirect Router memberi tahu bahwa ada jalur lebih baik – biasanya bukan indikasi masalah serius.
Request Timed Out Tidak ada balasan dari tujuan. Periksa firewall yang memblokir ICMP, atau host mati.

B. Teknik Konfigurasi Ulang & Perbaikan Internet Gateway

1. Verifikasi Konfigurasi Dasar

Langkah pertama dalam perbaikan adalah memastikan konfigurasi dasar sudah benar:

  • Periksa IP address, netmask, dan gateway pada setiap interface.
  • Pastikan IP forwarding aktif. Pada Linux: echo 1 > /proc/sys/net/ipv4/ip_forward (atau edit /etc/sysctl.conf).
  • Pada router Mikrotik, pastikan NAT rule untuk masquerade sudah dibuat: IP → Firewall → NAT → add chain=srcnat action=masquerade out-interface=Ether1-publik.

2. Mengatasi NAT yang Tidak Berfungsi

Jika klien tidak bisa akses internet meskipun gateway bisa di-ping, kemungkinan NAT bermasalah. Berikut langkah perbaikannya:

  • Cek aturan NAT – pastikan ada rule dengan action MASQUERADE atau SNAT pada interface publik.
  • Periksa koneksi tracking – pada Linux, conntrack -L untuk melihat tabel koneksi; jika penuh, tingkatkan ukuran net.netfilter.nf_conntrack_max.
  • Uji dengan ping dari router ke internet – jika router bisa ping 8.8.8.8, masalah ada di NAT atau firewall pada router.
  • Periksa routing – pastikan default route mengarah ke gateway ISP.

3. Port Forwarding untuk Akses Server dari Luar

Jika server di jaringan lokal (misal 192.168.88.10) perlu diakses dari internet, gunakan port forwarding (DNAT). Contoh pada Mikrotik:

/ip firewall nat
add chain=dstnat dst-address=202.123.123.100 protocol=tcp dst-port=80 \
    action=dst-nat to-addresses=192.168.88.10 to-ports=80

Pada Linux dengan iptables:

iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 -j DNAT --to-destination 192.168.88.10:80
iptables -A FORWARD -p tcp -d 192.168.88.10 --dport 80 -j ACCEPT

Pastikan juga ada aturan FORWARD yang mengizinkan lalu lintas masuk ke server internal.

4. Firewall dan Filtering

Kadang firewall di router atau server memblokir akses. Periksa:

  • Aturan INPUT – jangan sampai memblokir paket dari client atau internet.
  • Aturan FORWARD – harus mengizinkan paket yang melalui router (dari LAN ke WAN dan sebaliknya).
  • Jika menggunakan stateful firewall, pastikan aturan RELATED,ESTABLISHED diizinkan.

5. Masalah DNS

Jika klien bisa ping ke IP publik tetapi tidak bisa mengakses website, DNS tidak berfungsi. Solusi:

  • Pastikan DNS server di client (misal 192.168.88.1) dapat diakses dan berfungsi.
  • Uji dengan nslookup google.com dari client.
  • Jika DNS server internal bermasalah, set sementara DNS publik (8.8.8.8) di client untuk pengujian.

6. Langkah Praktis Perbaikan pada Router Mikrotik

  • Login ke Winbox atau WebFig.
  • Cek Interface – pastikan Ether1 dan Ether2 aktif (status running).
  • Cek IP → Addresses – pastikan IP publik dan lokal terpasang dengan benar.
  • Cek IP → Routes – pastikan ada default route dengan gateway ISP.
  • Cek IP → Firewall → NAT – pastikan rule masquerade ada dan aktif.
  • Gunakan Tools → Ping dari router ke 8.8.8.8 untuk verifikasi koneksi.
  • Jika semua sudah benar tetapi client tetap tidak bisa, periksa Bridge atau Switch jika menggunakan konfigurasi yang kompleks.
📌 Catatan penting: Setelah melakukan perubahan konfigurasi, selalu lakukan testing dari sisi client (ping, traceroute, browsing) untuk memastikan perbaikan berhasil. Jangan lupa untuk menyimpan konfigurasi (/system backup save pada Mikrotik) agar tidak hilang setelah reboot.

C. Studi Kasus Troubleshooting NAT

Kasus: Client di jaringan 192.168.88.0/24 tidak bisa mengakses internet, tetapi gateway (192.168.88.1) bisa di-ping. Router Mikrotik juga bisa ping ke 8.8.8.8.

Analisis: Karena gateway bisa di-ping, kemungkinan masalah ada di NAT atau aturan firewall FORWARD.

Langkah penyelesaian:

  1. Periksa aturan NAT di Mikrotik: IP → Firewall → NAT. Ternyata rule masquerade tidak ada.
  2. Tambahkan rule: chain=srcnat out-interface=Ether1-publik action=masquerade.
  3. Verifikasi dengan ping dari client ke 8.8.8.8 – berhasil.
  4. Uji browsing – berhasil.
  5. Dokumentasikan penambahan rule untuk referensi tim.

Kasus lain: Server web di 192.168.88.10 tidak bisa diakses dari internet meskipun port forwarding sudah dibuat.

Solusi: Periksa apakah ada aturan firewall INPUT atau FORWARD yang memblokir port 80. Tambahkan aturan ACCEPT untuk port 80 pada chain FORWARD, dan pastikan server lokal memiliki gateway yang benar (192.168.88.1).

Kesimpulan

Troubleshooting pada gateway dan NAT membutuhkan pendekatan sistematis, mulai dari pemeriksaan fisik hingga konfigurasi logis. Dengan memahami fungsi NAT, routing, dan firewall, serta menggunakan tools diagnostik yang tepat, sebagian besar permasalahan dapat diidentifikasi dan diselesaikan dengan cepat. Selalu dokumentasikan setiap perubahan dan solusi untuk memperkaya basis pengetahuan tim dan mempercepat proses penanganan di masa depan.
